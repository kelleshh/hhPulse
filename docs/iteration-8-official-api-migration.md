# Итерация 8 — официальный HH API вместо HTML вакансий

## Что изменено

Production-сбор вакансий переведён с `hh.ru/search/vacancy` на официальный `https://api.hh.ru/vacancies`.
HTML-парсер вакансий, browser-like заголовки, ротация User-Agent и WAF-эвристики удалены из production-кода.

Основной агрегатный запрос использует `clusters=true`, `no_magic=true` и `per_page=1`. Поле `found` является общим количеством вакансий. Если нужный фасет отсутствует в `clusters`, выполняется один точный запрос с соответствующим фильтром и читается только `found`.

`label=low_performance` используется для количества вакансий с менее чем 10 откликами. `label=with_salary` используется для количества вакансий с указанным доходом.

## Точные количества откликов

HH не предоставляет среднее или медиану откликов агрегатом. Для этого используется `responses_count_enabled=true`; выдача читается по 100 вакансий. В SQLite сохраняется не список вакансий, а компактная частотная таблица `{число_откликов: число_вакансий}`.

Чтобы не повторять один и тот же полный обход, точные отклики собираются только для страты опыта `ANY`. Если поисковая выдача превышает глубину 2000, активные вакансии рекурсивно делятся по интервалам публикации, а ID вакансий дедуплицируются.

Среднее/медиана публикуются только при полном покрытии ожидаемого `found`. Иначе они остаются `null`, чтобы частичная выдача не превращалась в статистическую ложь.

## Авторизация и rate limit

Нужны:

```dotenv
HHPULSE_HH_ACCESS_TOKEN=...
HHPULSE_HH_USER_AGENT=hhPulse/0.4 (your-email@example.com)
HHPULSE_COLLECT_RESPONSE_STATS=1
```

`docker-compose.yml` прокидывает эти переменные в backend. Rate limiter имеет один стабильный client identity, ограничивает глобальные RPS/concurrency и адаптивно замедляется на `429` с учётом `Retry-After`.

## Резюме

Production не подставляет нули вместо недоступных данных. Пока официальный employer-доступ к `GET /resumes` не подтверждён для конкретной организации, `resumes` и `hhIndex` равны `null`.

Для проверки оставлены два изолированных инструмента:

- `scripts/public_resume_count_probe.py` — один консервативный запрос публичной HTML-страницы на роль; немедленно прекращает работу на CAPTCHA/WAF/403/429 и ничего не обходит;
- `scripts/employer_resume_api_probe.py` — read-only проверка employer OAuth token, `method_access`, дневных лимитов и одного `GET /resumes?per_page=1`; не покупает доступ и не открывает индивидуальные резюме.
