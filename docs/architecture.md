# Архитектура hhPulse

Клиент открывает локальный сайт на `127.0.0.1`. API и сайт запускаются в Docker Compose, данные SQLite находятся в томе `hhpulse_data`. В том же Chrome-профиле открыто распакованное расширение с вкладкой сборщика. Оно делает поисковые загрузки HH в одной выделенной вкладке. Закрытие вкладки сборщика прекращает связь.

## Подготовка дня

`PrepareOrResumeDailyRun` создаёт одну запись запуска для пары `job_id × дата` и предварительно проверяет, что Chrome подключён. Дата начала 60-дневного окна резюме является частью каждого сохранённого `SearchQuery`; восстановление очереди на другой день не сдвигает границы старого запуска. Для каждого региона и общего опыта создаётся одна единица вакансий с ролью `*`. По одной единице добавляется на каждый выбранный фильтр. Для резюме добавляются единицы для каждой профессии и каждого выбранного фильтра.

Роли берутся из публичного справочника HH. Дерево вакансий применяется сразу ко всем выбранным профессиям; дерево резюме не применяется для полного счётчика. Срез удалённой работы соответствует `area=113`, `work_format=REMOTE`.

## Выполнение

`RunCrawlWorkerPool` запускает ровно одного работника даже для задач со старым числом параллельных работников. `BrowserMarketSource` отдаёт команду локальному мосту. Вкладка расширения получает команду, обновляет свою вкладку HH, читает видимый DOM и возвращает только агрегаты. Следующая загрузка начинается после паузы `2 + uniform(0, 2)` секунд. Вкладка расширения должна быть открыта; отсутствие связи переводит единицу в ожидание до конца дня.

Дерево вакансий раскрывается категория за категорией; виртуализированный список прокручивается с перекрытием. Если не посещены все категории, парсер возвращает ошибку и запуск не публикуется. Полный счётчик резюме сверяется с доступным и скрытым числами текущего поиска. URL страницы проверяется против сохранённых фильтров. Подробности — [browser-contract.md](browser-contract.md).

Завершённые единицы сохраняются в staging. После перезапуска исполнявшаяся единица возвращается в очередь. Только совпадение `total_units`, успешных единиц и staging-записей приводит к публикации в одной транзакции SQLite. Старые опубликованные данные остаются доступными. Аналитика разносит одно дерево вакансий по отдельным ролям и связывает с полным счётчиком резюме. Отфильтрованные поиски дают отдельные доли, не прибавляются к общему количеству.

CAPTCHA, отказ в доступе и нарушение контракта не получают бесконечных повторов. Отсутствие Chrome и временная потеря сети ожидают повторного подключения до полуночи в часовом поясе задачи. Данные другого аккаунта или реальные ограничения HH этим механизмом не обходятся.
