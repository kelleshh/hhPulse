# Контракт браузерного сбора

Расширение запрашивает следующую команду у `GET /api/v1/browser/next` и отдаёт результат через `POST /api/v1/browser/result`. Оба запроса требуют `X-HHPULSE-BROWSER-TOKEN` из локального `.env`. Сервер принимает только ответ для текущего ID команды. Связь доступна через локальный сайт; сервер Docker не обращается к профилю Chrome и не читает cookies.

Команда содержит `id`, URL `https://hh.ru/search/{vacancy|resume}` и тип поиска. Ответ содержит фактический URL и одно из состояний `ok`, `blocked`, `auth`, `contract`, `unavailable`. При `ok` ответ вакансий содержит `total`, массив `{id,name,count}` и `tree_complete=true`; ответ резюме содержит `total`, `visible`, `hidden`. Персональные карточки и HTML не передаются.

На странице поиска расширение нажимает `data-qa="header-search-filters-button"` и ждёт содержимое панели. Для вакансий затем нажимается `data-qa="search-filter-professional-role-trigger"`: дерево отсутствует в исходном DOM страницы и появляется только после этих двух действий. Сравниваются заголовок выдачи и число на кнопке фильтров, затем раскрываются категории дерева. ID роли извлекается из `data-qa` строки листа, имя из `cell-text-content`, число из `cell-chevron`. Одинаковый ID из нескольких категорий сохраняется один раз; разные числа для одного ID вызывают ошибку. Виртуализированный список прокручивается после раскрытия всех категорий. Если не достигнут `aria-setsize` категорий или пунктов внутри группы, результат отклоняется. Не показанные при полном дереве роли справочника получают ноль.

Для резюме после открытия панели кнопка `data-qa="search-drawer-filters-submit"` даёт общий счётчик; `data-qa="search-title"` даёт доступные резюме; баннер даёт скрытые. Сервер принимает результат только при равенстве `total = visible + hidden`. При отсутствии баннера `hidden=0`; тогда полный счётчик обязан совпасть с доступным. Каждая выбранная роль и фильтр проверяется собственным поиском. Число скрытых из одного поиска нельзя использовать для другого.

Сервер проверяет `area`, `professional_role`, `experience`, все выбранные фильтры и фиксированные даты по фактическому URL. Страницы ограничения и неожиданная разметка останавливают запуск. Протокол не доказывает, что HH никогда не изменит семантику фильтров: это требует проверки на живой странице после установки.
