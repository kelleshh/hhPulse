# hhPulse

Локальный сайт для ежедневных снимков рынка труда HH. Сбор страниц поиска выполняется в **текущем авторизованном Google Chrome работодателя** через небольшое локальное расширение. Регистрация приложения HH и OAuth-токен не нужны. Справочник профессий читается из открытого `GET /professional_roles`; при его недоступности используется снимок справочника из присланной страницы от 28.09.2026. Новые ID в дереве относительно снимка останавливают сбор.

## Что считается

- Вакансии: одна страница поиска на сочетание региона, общего опыта и выбранного фильтра. Расширение раскрывает всё виртуализированное дерево профессий, собирает ID и число вакансий по каждой роли. При неполном дереве дневной запуск не публикуется.
- Резюме: отдельная страница поиска **на каждую роль и фильтр**. Учитывается полное число результатов. Если HH показывает доступные и скрытые отдельно, проверяется `полное = доступные + скрытые` для **того же поиска**. Дерево профессий резюме не используется.
- Резюме ограничены последними 60 календарными днями с фиксированными для дневного запуска `date_from` и `date_to`. Статусы: `unknown`, `active_search`, `looking_for_offers`. Релокация: `living_or_relocation`.
- Режим опыта: общий итог либо общий итог и четыре группы (без опыта, 1–3, 3–6, более 6 лет). Для дополнительного среза снова считается полная выдача внутри каждой группы.
- «Удалёнка · вся Россия» ищет по `area=113` и `work_format=REMOTE`. Для обычного региона география остаётся выбранной.
- Дополнительные срезы включаются галочками: вакансии с менее 10 откликами, наличие зарплаты, формат работы, занятость, образование; для резюме — наличие желаемой зарплаты, формат работы, занятость и образование. Зарплатные интервалы не собираются. Форма заранее показывает число поисковых загрузок и приблизительное время.

Среднее и медиана откликов требуют обхода карточек вакансий и здесь не собираются. Отсутствующая метрика остаётся `null`, а не нулём. Задачи получают методологию `hh-browser-complete-count-v1`. Существующие задачи и опубликованные снимки в SQLite сохраняются; старые наблюдения остаются историческими без нового маркера методологии.

## Запуск

Нужны Docker Compose v2, Python 3 на локальном компьютере и Google Chrome с уже открытой работодателем сессией HH.

```bash
./deploy.sh
./deploy.sh browser-token
```

1. Откройте `chrome://extensions`, включите «Режим разработчика» и загрузите папку `browser-extension` как распакованное расширение.
2. Нажмите на значок **hhPulse browser companion**. В открывшейся вкладке укажите адрес локального сайта (обычно `http://localhost:3000`) и токен из второй команды.
3. Нажмите «Подключить» и оставьте вкладку сборщика открытой. В `http://localhost:3000` создайте задачу и запустите её. Поиск будет виден в отдельной вкладке HH.

Скрипт `deploy.sh` создаёт `.env` и случайный `HHPULSE_BROWSER_TOKEN`, если токена ещё нет. Файл `.env` и том `hhpulse_data` при обновлении не удаляются. Для сервера без GUI нужен Chrome на той же машине, где доступен локальный сайт, либо доступ к нему через безопасное локальное соединение; браузерный сбор не работает без открытой вкладки расширения.

Очередь строго последовательная. После каждого поиска стоит пауза от 2 до 4 секунд. При потере браузера или сети задача ждёт в пределах дня, а после перезапуска продолжает сохранённые единицы. При CAPTCHA, отказе в доступе, неоднозначном счётчике и изменении структуры страницы публикация останавливается. Настройка темпа снижает нагрузку, но не гарантирует отсутствие ограничений HH.

## Данные и код

SQLite хранит задачи, позиции очереди, промежуточные наблюдения, события и опубликованные снимки. Публикация полного дневного результата атомарна. Расширение передаёт только URL поиска, ID профессий и агрегатные числа: cookies, карточки резюме и контакты не экспортируются.

- [`docs/architecture.md`](docs/architecture.md) — поток данных и возобновление.
- [`docs/browser-contract.md`](docs/browser-contract.md) — проверка чисел и локальный протокол.
- `src/hhpulse/domain` — предметные правила; `application` — план и очередь; `infrastructure` — Chrome, справочник, SQLite; `api` — интерфейс сайта.
